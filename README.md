# Репозиторий для освоения MicroPython

Данный репозиторий содержит инструкции, примеры и настройки для работы с платами **ESP8266 NodeMCU** и **PyBoard v1.1** под управлением MicroPython. Здесь описаны подключение, прошивка, настройка окружения разработки, сборка интерпретатора из исходников и структура типового проекта.

---

## 1. Железо

- **ESP8266 NodeMCU**  
  Чип USB‑UART: CP210x (Silicon Labs)
- **PyBoard v1.1**  
  Встроенный USB‑контроллер, режим CDC ACM

---

## 2. Подключение к компьютеру

### 2.1 Определение устройства в системе

Проверьте, как система определяет подключённую плату, с помощью команды `lsusb`:

```bash
lsusb
```

**Пример вывода:**

- Для **ESP8266**:
  ```
  Bus 001 Device 002: ID 10c4:ea60 Silicon Labs CP210x UART Bridge
  ```
- Для **PyBoard**:
  ```
  Bus 001 Device 002: ID f055:9800 MicroPython Pyboard Virtual Comm Port in FS Mode
  ```

### 2.2 Просмотр последовательного порта

Общая команда для поиска последовательных портов:

```bash
ls -l /dev/ttyUSB* /dev/ttyACM* 2>/dev/null
```

**Пример для ESP8266:**
```
crw-rw---- 1 root dialout 188, 0 Jul 29 20:19 /dev/ttyUSB0
```

**Для PyBoard** можно также использовать символические ссылки:
```bash
ls -l /dev/serial/by-id/
```
Вывод:
```
usb-MicroPython_Pyboard_Virtual_Comm_Port_in_FS_Mode_206C36745853-if01 -> ../../ttyACM0
```

### 2.3 Права доступа

Если недостаточно прав или вы не входите в группу `dialout`, добавьте своего пользователя в эту группу:

```bash
sudo usermod -a -G dialout $USER
```

После этого **перелогиньтесь** (выйдите и зайдите заново или перезагрузите сессию).

### 2.4 Особенности работы с платами

- **PyBoard** в Ubuntu определяется как съёмный диск с двумя скриптами: `boot.py` и `main.py`.  
  При подаче питания сначала выполняется `boot.py`, затем `main.py`.  
  При автоматическом запуске глобальная переменная `__name__` равна `"__main__"`.

- **ESP8266** подключается только как последовательный порт; файловая система доступна через **FTP** или **WebREPL** (при необходимости).

## 3. Работа с REPL (интерактивная среда)

### 3.1 Подключение к интерпретатору

Используйте программу `screen` для подключения к последовательному порту:

- Для ESP8266:
  ```bash
  screen /dev/ttyUSB0
  ```
- Для PyBoard:
  ```bash
  screen /dev/ttyACM0
  ```

После подключения вы попадёте в приглашение Python `>>>`. Для выхода из `screen` нажмите `Ctrl+A`, затем `K` и подтвердите.

### 3.2 Особенности `__name__` в REPL

При импорте модуля из REPL значение `__name__` будет равно имени модуля (например, `"main"`), а не `"__main__"`. Это важно при тестировании модулей, написанных с условием `if __name__ == "__main__":`.

## 4. Работа с файловой системой (форматирование флеш-накопителя)

Если требуется отформатировать внешнюю флешку (например, для использования с платой), выполните:

```bash
sudo umount /media/...                 # отмонтировать текущий раздел
sudo mkfs.vfat -F 32 -s 8 -S 512 -n 'MYPYMEM' /dev/sdb   # форматировать в FAT32
```

*Внимание: замените `/dev/sdb` на актуальное устройство, чтобы не потерять данные.*

## 5. Прошивка новой версии (на примере PyBoard)

### 5.1 Установка dfu-util

```bash
sudo apt install dfu-util
```

### 5.2 Перевод платы в режим DFU

На **PyBoard v1.1** замкните перемычкой контакты **BOOT0** и **3.3V**, затем подайте питание (или нажмите кнопку сброса). После этого плата появится как DFU-устройство.

Проверьте, что устройство обнаружено:
```bash
sudo dfu-util -l
```

### 5.3 Дамп текущей прошивки (резервное копирование)

```bash
sudo dfu-util --alt 0 --upload pyboard-original.dat -s:524288
```

### 5.4 Загрузка новой прошивки

Скачайте нужный DFU-файл (например, `PYBV11-20260406-v1.28.0.dfu`) и выполните:

```bash
sudo dfu-util --alt 0 -D PYBV11-20260406-v1.28.0.dfu
```

После завершения отключите питание и снимите перемычку с BOOT0.

## 6. Настройка окружения для разработки в IDE

### 6.1 Установка утилит

Установите необходимые инструменты:

```bash
pip install --user mpremote
pip install mip
pip install micropython-stubber
```

### 6.2 Генерация заглушек (stubs) для автодополнения

Инициализируйте каталог для заглушек:

```bash
stubber init
```

Пример вывода:

```bash
stubber get --port /dev/ttyACM0
```

```bash
pip install ./publish/micropython-v1_28_0-stm32-pybv11-stubs
```

Теперь IDE будет подсказывать функции и модули MicroPython.

## 7. Сборка MicroPython из исходного кода

Если нужно собрать интерпретатор для **Unix** (например, для тестирования на ПК), выполните следующие шаги.

### 7.1 Установка зависимостей

```bash
sudo apt-get install build-essential libreadline-dev libffi-dev git pkg-config gcc-arm-none-eabi libnewlib-arm-none-eabi
```

### 7.2 Клонирование репозитория

```bash
git clone --recurse-submodules https://github.com/micropython/micropython.git
cd micropython/
```

### 7.3 Сборка кросс-компилятора и интерпретатора

```bash
make -C mpy-cross
make -C ports/unix submodules
make -C ports/unix
```

### 7.4 Проверка работоспособности

```bash
./ports/unix/build-standard/micropython -V
# Должно вывести: MicroPython vx.x.x
```

### 7.5 Установка в систему

```bash
sudo mkdir -p /opt/micropython/bin
sudo cp ./ports/unix/build-standard/micropython /opt/micropython/bin/
sudo chmod +x /opt/micropython/bin/micropython
```

Создайте символическую ссылку для удобства:

```bash
sudo ln -s /opt/micropython/bin/micropython /usr/local/bin/micropython
```

Проверьте:

```bash
which micropython
micropython -c "import sys; print(sys.version)"
```

## 8. Структура проекта MicroPython

Рекомендуемая структура каталогов для разработки:

```
my_micropython_project/
├── main.py                # Точка входа. Выполняется автоматически при включении устройства
├── boot.py                # (Опционально) Скрипт, выполняющийся ДО main.py (настройка сети и т.д.)
├── config.py              # Настройки (SSID, пароли, пины)
├── lib/                   # Локальные библиотеки (для автодополнения и копирования на плату)
│   ├── my_sensor.py
│   └── utils.py
├── scripts/               # Скрипты автоматизации (деплой, тестирование)
├── requirements.txt       # Список пакетов для установки через mip на устройство
└── Makefile               # Для быстрых команд деплоя
```

**Описание файлов:**

- `boot.py` – выполняется перед `main.py`; подходит для инициализации сети, подключения к Wi-Fi.
- `main.py` – главный цикл приложения.
- `config.py` – хранит конфигурационные параметры (пароли, пины) – не включайте в репозиторий с секретами.
- `lib/` – здесь можно размещать свои модули, которые затем копируются на плату.
- `requirements.txt` – содержит имена пакетов, устанавливаемых через `mip` (например, `urequests`, `umqtt.simple`).
- `Makefile` – автоматизирует копирование файлов на плату (см. следующий раздел).

## 9. Makefile для автоматизации

Пример простого `Makefile`, который загружает все файлы на плату через `mpremote`:

```makefile
PORT ?= /dev/ttyACM0

.PHONY: run deploy

deploy:
	mpremote connect $(PORT) cp -r lib/ :lib/
	mpremote connect $(PORT) cp main.py config.py :.

run:
	mpremote connect $(PORT) run main.py

reset:
	mpremote connect $(PORT) reset
```

Использование:
```bash
make deploy   # копирует файлы на плату
make run      # запускает main.py без копирования
make reset    # перезагружает плату
```
